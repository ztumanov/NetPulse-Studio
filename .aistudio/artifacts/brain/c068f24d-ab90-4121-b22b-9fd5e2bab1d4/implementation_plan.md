# NetPulse Studio — Интерактивный Web-симулятор компьютерных сетей (L2/L3)

Веб-приложение для проектирования сетевых топологий, настройки оборудования (включая интерфейс командной строки в стиле Cisco IOS) и наглядной пошаговой визуализации прохождения пакетов (ARP, ICMP, TCP/UDP, маршрутизация и VLAN) по модели OSI в реальном времени.

---

- **Ключевой функционал первой версии (Подтверждено)**:
  1. Визуальная анимация движения пакетов (ICMP / ARP / TCP) по линкам между узлами и пошаговый инспектор заголовков PDU (OSI L1–L4).
  2. Настройка интерфейсов (IPv4, маска подсети, шлюз по умолчанию), таблиц маршрутизации, портов VLAN (Access / Trunk) и встроенный интерактивный CLI-терминал в стиле Cisco IOS.
- **Визуальное оформление (Подтверждено)**: Инженерная тёмная тема **NetOps Dark** (`#0F172A` / `#1E293B`) с тактильной координатной сеткой и контрастной семантической индикацией состояния портов, кабелей и типов пакетов.
- **Рекомендуемый стек и хранение (По умолчанию)**:
  - **Ядро фронтенда**: React 19 + TypeScript + Tailwind CSS + Lucide Icons + Motion (для плавной интерполяции движения пакетов).
  - **Рендеринг топологии**: Гибридный SVG + HTML-слой с аппаратно-ускоренным панорамированием/зумом (позволяет рендерить чёткие векторные узлы, кривые/прямые кабели, портовые индикаторы и анимированные маркеры пакетов без размытия на любых экранах).
  - **Сетевой движок**: Чистый детерминированный TypeScript-движок дискретно-событийной симуляции (Discrete Event Network Engine), полностью отделённый от UI, что гарантирует мгновенный расчёт маршрутов, таблиц MAC/ARP и поддержку пошагового режима (`Step Forward` / `Play` / `Pause`).
  - **Хранение проектов**: Автосохранение в `localStorage` браузера + экспорт/импорт топологий в формате `.json` и готовые преднастроенные лабораторные сценарии (шаблоны сетей) для быстрого старта.

## 1. Overview & Core Concept

- **Что делает приложение**: Позволяет собирать сетевые схемы из маршрутизаторов (Router), коммутаторов (Switch L2), рабочих станций (PC) и серверов (Server), соединять их патч-кордами по конкретным портам (`FastEthernet0/0`, `GigabitEthernet0/1`), настраивать адресацию через графический инспектор или консоль Cisco IOS CLI и наблюдать, как именно пакеты формируются, инкапсулируются и проходят через каждый узел сети.
- **Целевая аудитория**: Студенты сетевых академий (CCNA / сетевые инженеры), преподаватели и разработчики, которым нужна быстрая браузерная альтернатива Cisco Packet Tracer без установки тяжёлого десктопного ПО.
- **Главная ценность**: Прозрачность работы сети — пользователь видит не просто результат `Reply from 192.168.2.10`, а каждый промежуточный шаг: почему сначала отправляется широковещательный `ARP Request`, как коммутатор записывает MAC-адрес в CAM-таблицу, как отсекается трафик другого VLAN и как маршрутизатор перезаписывает L2-заголовки при переходе между подсетями.

## 2. User Experience & Visual Design

### Ключевые пользовательские сценарии (User Flows)

1. **Быстрый старт через готовые лабораторные топологии или создание с нуля**:
   - При открытии рабочего пространства загружается демонстрационная работоспособная топология (например, *«Две подсети через маршрутизатор и VLAN-коммутатор»*), чтобы симуляцию можно было запустить в один клик, либо переключиться на другой шаблон (*«Широковещательный шторм и ARP»*, *«Маршрутизация между 3 офисами»*, *«Чистый холст»*).
2. **Построение физической топологии на холсте**:
   - Выбор устройства в палитре оборудования (Router, Switch, PC, Server) и размещение на координатной сетке с поддержкой Drag-and-Drop.
   - Инструмент «Кабель» (Copper Straight-Through / Crossover / Fiber): клик по первому устройству открывает компактный селектор свободных портов (`Fa0/0`, `Gi0/1`), клик по второму устройству завершает коммутацию и зажигает индикаторы состояния линка.
3. **Настройка узла (GUI + Cisco IOS CLI)**:
   - Клик по любому устройству открывает правую панель инспектора с тремя вкладками:
     - **Конфигурация (GUI)**: быстрая настройка Hostname, IP/Mask интерфейсов, Default Gateway, таблиц статической маршрутизации и режимов портов коммутатора (`Access VLAN` / `Trunk Allowed VLANs`).
     - **Терминал (IOS CLI)**: интерактивная консоль с поддержкой режимов `User EXEC (>)`, `Privileged EXEC (#)`, `Global Config (config)#` и `Interface Config (config-if)#`. Команды в CLI (`enable`, `configure terminal`, `interface fa0/0`, `ip address ...`, `no shutdown`, `vlan 10`, `show ip interface brief`, `show mac address-table`, `show arp`, `ping <ip>`) мгновенно синхронизируются с состоянием устройства и GUI.
     - **Таблицы состояния (State Tables)**: просмотр живых таблиц ARP, MAC-таблицы коммутатора и таблицы маршрутизации в реальном времени.
4. **Режим симуляции и инспекция пакетов (Realtime vs Simulation Mode)**:
   - Пользователь выбирает инструмент **«Отправить пакет (Add Simple PDU / Ping)»**, указывает узел-источник и узел-назначение, либо вводит `ping 192.168.2.20` в терминале ПК.
   - В пошаговом режиме (**Simulation Mode**) время управляется контроллером (`Play / Pause`, `Step Forward`, `Step Back`, ползунок скорости `0.5x – 4x`).
   - На каждом шаге пакет плавно перемещается по кабелю. Клик по пакету на холсте или строке в журнале событий (**Event List**) открывает **Инспектор PDU (OSI Model Layer View)**, где наглядно показаны входящие (`Inbound PDU`) и исходящие (`Outbound PDU`) заголовки уровней L1 (Порты), L2 (Ethernet II / 802.1Q: Src MAC, Dst MAC, VLAN tag), L3 (IPv4: Src IP, Dst IP, TTL) и L4/Payload (ICMP Echo Request / Reply, ARP Request / Reply, TCP Syn).

### Визуальная система и тема (NetOps Dark)

- **Эстетическое направление**: Высокоточный инженерный интерфейс в духе современных систем сетевой телеметрии и САПР (CAD). Двухзонная архитектура песочницы: $70\%$ экрана занимает интерактивный топологический холст с технической сеткой, $30\%$ — правая и нижняя панели управления симуляцией, инспекции PDU и CLI-терминала.
- **Цветовая палитра (60-30-10 Budget)**:
  - **60% Доминирующий холст (`--background`)**: Глубокий графитово-сланцевый `#0F172A` (`slate-900`) с точечной/линейной координатной сеткой `#1E293B`.
  - **30% Структурные панели (`--surface`)**: Инженерные панели `#1E293B` (`slate-800`) с тонкими разделителями `1px solid #334155` (`slate-700`), основной текст `#F8FAFC`, вторичный `#94A3B8`.
  - **10% Семантические акценты состояния и протоколов** (всегда в паре с текстовыми метками и иконками, без опоры только на цвет):
    - `● UP / FORWARDED`: Изумрудный `#10B981` (`emerald-500`) — активный порт и успешная доставка пакета.
    - `▲ ARP / BROADCAST`: Янтарный `#F59E0B` (`amber-500`) — широковещательные ARP-запросы и поиск маршрута.
    - `◆ ICMP / PING`: Лазурный `#0EA5E9` (`sky-500`) — эхо-запросы и ответы диагностики.
    - `✕ DROPPED / DOWN`: Кораллово-красный `#EF4444` (`red-500`) — административно выключенный порт (`shutdown`), несовпадение VLAN, истечение TTL или отсутствие маршрута (`Unreachable`).
- **Типографика и иерархия (Правило 2+1)**:
  - **Заголовки и навигация**: `Plus Jakarta Sans` (SemiBold 600) — чёткая геометрическая читаемость элементов управления.
  - **Основной интерфейс**: `DM Sans` (Regular 400 / Medium 500) — компактные подписи инспектора и пояснения шагов OSI.
  - **Сетевая телеметрия, IP/MAC-адреса, PDU и CLI**: `JetBrains Mono` с `font-variant-numeric: tabular-nums` — строгое вертикальное выравнивание IP-адресов, масок, MAC-таблиц и байтовых полей пакета.

## 3. Key Product Decisions & Trade-Offs (Выбор стека и архитектуры)

### 1. Стек рендеринга холста: Интерактивный SVG + HTML Overlay вместо тяжёлого WebGL
- **Выбранный подход**: Использование масштабируемого векторного SVG-слоя для соединительных линий (патч-кордов), индикаторов портов и траекторий пакетов в сочетании с аппаратно-ускоренными узлами устройств и контроллером трансформации (`pan` / `zoom`).
- **Почему**: В сетевом симуляторе типа Packet Tracer количество узлов на учебном стенде обычно составляет от 4 до 40 устройств, но критически важна абсолютная чёткость текста (IP-адреса, подписи портов `Gi0/1`, VLAN ID), удобство клика по конкретному кабелю/пакету и доступность DOM-дерева.
- **Альтернативы**: Низкоуровневый PixiJS/WebGL избыточен для 2D-схем сетей и усложняет рендеринг чёткой типографики и контекстных меню, а готовые тяжеловесные библиотеки диаграмм часто ограничивают кастомную анимацию пакетов с остановкой на каждом порту.

### 2. Архитектура сетевого движка: Детерминированная пошаговая модель (Discrete Event Tick Engine)
- **Выбранный подход**: Выделение сетевой логики в независимое ядро (`src/network/`), где каждое действие (отправка кадра в порт, обработка коммутатором, маршрутизация пакетов) представляет собой дискретный шаг (`SimulationStep`) с полной записью состояния `Inbound PDU`, `Outbound PDU` и причины решения (`Decision Log`).
- **Почему**: В реальной жизни пакет пролетает локальную сеть за доли миллисекунды. Чтобы пользователь мог изучить работу протоколов, симулятор должен заранее или пошагово вычислять цепочку событий (например: *PC1 хочет пинговать PC2 -> в ARP-кэше нет MAC -> PC1 ставит ICMP в очередь и генерирует ARP Broadcast -> Switch размножает кадр по всем портам своего VLAN -> PC2 отвечает ARP Unicast -> PC1 отправляет ICMP Echo Request*), позволяя ставить воспроизведение на паузу и прокручивать шаги вперёд и назад.

### 3. Двусторонняя синхронизация GUI и Cisco IOS CLI
- **Выбранный подход**: Единый источник истины (Single Source of Truth) для конфигурации каждого сетевого устройства. Парсер команд CLI и формы визуального инспектора изменяют одну и ту же структуру данных устройства.
- **Почему**: Новичкам проще задать IP-адрес через текстовое поле в инспекторе, а продолжающим важно практиковать реальные команды `interface fa0/0` -> `ip address 192.168.1.1 255.255.255.0` -> `no shutdown`. При этом внизу панели настроек можно видеть эквивалентную команду IOS, которая соответствует только что сделанному действию в GUI.

### Модель данных (Data Model & Entities)

1. **Узел сети (`NetworkNode`)**:
   - `id`, `name` (Hostname), `type` (`'router' | 'switch' | 'pc' | 'server'`), координаты `{ x, y }` на холсте.
   - `interfaces`: массив сетевых портов (`NetworkInterface`), каждый содержит `id`, `name` (`Fa0/0`, `Gi0/1`), `macAddress`, `ipAddress`, `subnetMask`, `adminStatus` (`up` / `down`), `vlanMode` (`access` / `trunk`), `accessVlan` (число, по умолчанию `1`), `trunkAllowedVlans` (массив VLAN ID).
   - `routingTable`: список статических и подключённых маршрутов (`network`, `mask`, `nextHop`, `interface`).
   - `arpTable`: таблица соответствия `IPv4 -> MACAddress`.
   - `macTable` (для коммутаторов): таблица соответствия `MACAddress -> { portId, vlan }`.
2. **Соединение (`NetworkLink`)**:
   - `id`, `sourceNodeId`, `sourcePortId`, `targetNodeId`, `targetPortId`, `cableType` (`'straight' | 'crossover' | 'fiber'`), вычисляемый статус линка (`up` если оба порта `adminStatus === 'up'`, иначе `down`).
3. **Пакет и шаг симуляции (`PacketPDU` & `SimulationEvent`)**:
   - Заголовки OSI:
     - **L1**: `inPort`, `outPort`, `cableType`.
     - **L2 (Ethernet)**: `srcMac`, `dstMac` (включая `FF:FF:FF:FF:FF:FF`), `etherType` (`0x0800` IPv4, `0x0806` ARP), `vlanTag` (`null` или ID 802.1Q).
     - **L3 (IPv4)**: `srcIp`, `dstIp`, `ttl`, `protocol` (`ICMP`, `TCP`, `UDP`).
     - **L4 / Payload**: тип сообщения (`ARP Request`, `ARP Reply`, `ICMP Echo Request`, `ICMP Echo Reply`, `HTTP GET`), идентификатор сессии и статус шага (`forwarded`, `broadcast`, `delivered`, `dropped`).
   - Пояснение шага (`explanation`): подробный список действий, которые выполнило устройство при приёме и отправке пакета (например, *«Коммутатор SW-1 изучил MAC источника 00:1A:2B:01 на порту Fa0/1 (VLAN 10). MAC назначения FF:FF:FF:FF:FF:FF является широковещательным — кадр направлен во все активные порты VLAN 10, кроме входящего»*).

### Поэтапный план реализации (Roadmap внутри сборки)

1. **Этап 1: Ядро сетевой симуляции и математика протоколов (`src/network/`)**:
   - Реализация чистых функций побитовой IPv4-адресации (проверка принадлежности одной подсети, расчёт адреса сети, Longest Prefix Match для таблиц маршрутизации).
   - Реализация логики L2-коммутатора (динамическое обучение MAC-адресов, фильтрация по Access/Trunk VLAN, flooding неизвестных unicast и broadcast-кадров).
   - Реализация логики L3-маршрутизатора и конечных хостов (проверка своего/чужого сегмента, генерация `ARP Request` при пустом ARP-кэше, декремент TTL, перезапись MAC-адресов на каждом хопе).
   - Реализация интерпретатора команд Cisco IOS CLI (`enable`, `conf t`, `int`, `ip address`, `no shut`, `vlan`, `switchport`, `ip route`, `show running-config`, `show ip route`, `show arp`, `show mac address-table`, `ping`, `traceroute`).
2. **Этап 2: Интерактивный топологический холст и палитра устройств**:
   - Построение векторного холста с поддержкой перемещения узлов, масштабирования, отображения портовых индикаторов (зелёный кружок / красный треугольник) и подписей IP/VLAN.
   - Инструменты создания связей с выбором конкретного свободного интерфейса и инструмента отправки тестового пакета между двумя кликнутыми устройствами.
3. **Этап 3: Контроллер пошаговой анимации и инспектор OSI PDU**:
   - Панель управления временем симуляции (`Play/Pause`, `Step Back`, `Step Forward`, `Reset Simulation`), синхронизированная с плавной анимацией иконок пакетов вдоль кабелей.
   - Детальное окно разбора пакета по уровням модели OSI (вкладки *OSI Model Layers* и *Outbound PDU Details* как в классическом Cisco Packet Tracer).
4. **Этап 4: Готовые лабораторные сценарии и хранение проектов**:
   - Предварительно настроенные интерактивные сценарии:
     1. *«Маршрутизация между двумя подсетями (Router-on-a-Stick / L3 Gateway)»*
     2. *«Сегментация сети с помощью VLAN (Access & Trunk 802.1Q)»*
     3. *«Анатомия ARP и ICMP Ping в локальной сети»*
   - Экспорт/импорт конфигурации топологии в JSON и автоматическое тестирование сетевого ядра модульными тестами.
